# Hof — продукт

Статус: утверждён (Phase 1, 2026-10-05).

## 1. Что такое Hof

Hof — небольшой набор веб-приложений, который один человек разворачивает на своём сервере для себя, семьи или небольшой группы людей.

Hof Core даёт общее: аккаунты, вход и одну точку входа во все приложения. Полезную работу делают приложения. Первое из них — **Säckel**, бюджет по мешкам: деньги раскладываются по «мешкам» (категориям расходов), траты берутся из мешков, и всегда видно, сколько ещё можно потратить. Это метод конвертного бюджета в средневековом виде: бумажных конвертов нет, есть мешки с монетами.

## 2. Ценность

- Свои данные у себя: свой сервер, без облаков и подписок.
- Один аккаунт на все приложения Hof.
- Новое приложение становится частью работающей системы, а не отдельным продуктом со своим входом и своим обслуживанием.
- Систему понимает и сопровождает один человек. Hof, который автор перестал понимать, бесполезен, сколько бы он ни умел.

## 3. Пользователи

- **Администратор** — тот, кто развернул Hof. Создаёт аккаунты, обслуживает систему и пользуется приложениями наравне с остальными.
- **Пользователь** — член семьи или друг, которому администратор создал аккаунт. Пользуется приложениями, меняет свой пароль.

В первом релизе администратор Hof и владелец сервера, который его обслуживает, — один и тот же человек; отдельной роли оператора нет.

Регистрации нет. Без аккаунта доступна только страница входа.

## 4. Основные сценарии

1. **Развернуть.** Администратор устанавливает Hof на свой сервер по инструкции.
2. **Первый запуск.** Администратор создаёт свой аккаунт и попадает в Hof.
3. **Добавить человека.** Администратор создаёт аккаунт и передаёт человеку данные для входа.
4. **Войти и открыть приложение.** Пользователь входит один раз и открывает Säckel без повторного входа.
5. **Начать бюджет.** Пользователь создаёт мешки, записывает доход и распределяет его по мешкам.
6. **Записать трату.** Быстро, в том числе с телефона: сумма, мешок, дата, заметка.
7. **Следить за бюджетом.** Видеть остаток каждого мешка и сколько денег ещё не распределено, перекладывать деньги между мешками.
8. **Исправить ошибку.** Найти операцию в истории, изменить или удалить её.
9. **Вернуть доступ.** Если пользователь забыл пароль, администратор его сбрасывает. Если пароль забыл администратор, у него есть способ вернуть доступ.
10. **Отключить человека.** Администратор отключает пользователя, и тот сразу теряет доступ.
11. **Обслуживать.** Администратор обновляет Hof, делает резервные копии и при необходимости восстанавливается из них.

## 5. Scope первого usable release

Цель: развернуть Hof у себя, войти и каждый день реально вести бюджет в Säckel. Интерфейс на русском языке.

**Hof Core**

- Создание первого администратора при первом запуске. Этот шаг защищён: стать первым администратором может только тот, кто развернул Hof. Больше при первом запуске ничего не настраивается; конфигурация развёртывания задаётся вне интерфейса.
- Вход, выход, «кто я». Сессия истекает со временем и завершается при отключении пользователя.
- Две роли: администратор (в первом релизе один) и пользователь.
- Управление пользователями для администратора: создать, сбросить пароль, отключить, включить.
- Смена своего пароля.
- Главная страница со списком приложений (в первом релизе только Säckel).
- Немного анимации, звука и тихой музыки без слов как украшение двора. В «Моих покоях» их включают и настраивают на каждом устройстве, у нового пользователя всё выключено; без них всё работает так же.

**Säckel** — именно бюджет по мешкам, а не полноценная система личных финансов.

- У каждого пользователя свой личный бюджет, другие его не видят.
- Мешки: создать, переименовать, выбрать знак из готового набора, архивировать, восстановить из архива.
- Операции: доход, распределение по мешкам, расход, перенос между мешками. Их можно просматривать, исправлять и удалять.
- Остатки мешков и сумма нераспределённых денег.
- Удобная работа с телефона в браузере.

**Эксплуатация**

- Развёртывание на одном сервере по одной инструкции.
- Обновление без потери данных.
- Документированное резервное копирование и восстановление.
- Способ вернуть доступ администратору.

## 6. Не входит в первый релиз

**Hof Core**

- Каталог приложений, установка и удаление приложений из интерфейса.
- Управление внешними self-hosted продуктами (Vaultwarden и т. п.).
- Несколько администраторов, роли, группы, доступ к приложению только для части пользователей.
- Регистрация, приглашения, email, двухфакторный вход, вход через внешние аккаунты.
- Список активных сессий. Удаление пользователей: только отключение.
- Настройки в интерфейсе, которые ничего не меняют.
- Уведомления, общий поиск, хранилище файлов, журнал действий.

**Säckel**

- Счета и сверка с банком.
- Месяцы и периоды бюджета.
- Цели, долги, повторяющиеся операции.
- Импорт выписок и синхронизация с банком.
- Отчёты и графики.
- Несколько валют.
- Общий бюджет на нескольких пользователей.
- Группы и цвета мешков, свои картинки для мешков.

**Общее**

- Несколько языков интерфейса и подготовка к ним (i18n), выбор темы оформления.
- Мобильное приложение и offline-режим.
- Публичный API для сторонних клиентов.
- Общая библиотека интерфейса, SDK и plugin system, пока нет второго приложения.
- Анимации и звуки сверх утверждённого UI первой версии.

## 7. Границы ответственности

**Hof Core** отвечает за пользователей, вход, различие «администратор или пользователь», первый запуск и общие экраны: вход, главную, свой аккаунт и управление пользователями. Пользователь входит в Hof один раз, а приложения используют эту же идентичность без повторного входа.

Core не отвечает за данные, логику и настройки приложений, за общий UI-кит и SDK, за установку, обновление и резервное копирование приложений. В первом релизе это делает администратор по инструкции.

Правило: если функция нужна только одному приложению, она живёт в этом приложении.

**Приложение Hof** — логически самостоятельная часть системы: свой интерфейс, своя логика и свои данные, которыми владеет только оно. Своего входа и своих аккаунтов у приложения нет: оно работает с пользователем, который вошёл в Hof. Приложение не читает данные Core и других приложений напрямую, а Core не знает о данных приложения. В первом релизе приложение добавляет разработчик, а не администратор через интерфейс. Общий механизм подключения приложений проектируется после появления второго приложения.

**Säckel** отвечает за мешки, операции, остатки и правила бюджета, за свои данные и свой интерфейс со своей визуальной идентичностью. Säckel не занимается пользователями и входом и не работает отдельно от Hof.

## 8. Риски повторения Hof v1

- **Свой identity provider.** В v1 вход был отдельным сервисом с собственными токенами и ключами. Защита: самая простая модель, которая даёт один вход во все приложения.
- **Платформа приложений раньше второго приложения.** Защита: правило второго случая; в первом релизе список приложений фиксирован.
- **Общие пакеты с первого дня.** В v1 общий UI и серверный kit подключались через submodules. Защита: повторить код, а не выносить его, пока нет второго потребителя.
- **Разрастание Säckel.** В v1 MVP включал счета, периоды, цели, долги, несколько тем и «заложенную архитектурно» локализацию. Защита: в первом релизе только мешки и операции; «заложить архитектурно» под запретом.
- **Дробление на репозитории и компоненты.** В v1 у каждого компонента был свой репозиторий и вложенные submodules. Защита: граница между Core и приложением — это владение функциями и данными, а не отдельный репозиторий. Сколько процессов нужно, решается в архитектуре.
- **Эксплуатационная машинерия.** В v1 были hofctl, plan/apply, operation journal, release locks, подписи релизов, SBOM. Защита: собственный инструмент появляется, только когда ручная операция реально и регулярно мешает.
- **Настройки, которые ничего не меняют.** Защита: настройка появляется только вместе с тем, что её использует.

## 9. Критерии успеха

1. На чистом сервере Hof разворачивается по инструкции примерно за 30 минут, без правок кода и без импровизации.
2. Автор ведёт свой реальный бюджет в Säckel не меньше 4 недель подряд и записывает все траты. Ещё как минимум один человек пользуется Hof со своим аккаунтом.
3. За это время хотя бы одно обновление и одно восстановление из резервной копии прошли без потери данных.
4. Пользователь не видит чужие данные, а отключённый пользователь сразу теряет доступ. Оба свойства проверены тестами.
5. Автор объясняет всю систему одной схемой на одной странице и может сказать, зачем нужна каждая её часть.
6. Ничего из раздела 6 не реализовано «заодно».
